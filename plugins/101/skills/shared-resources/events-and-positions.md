# События и позиции

- У события два слоя терминов. При создании, подтверждении и описании результата называй точный подтип из формы создания. Название категории из фильтра/истории используй только при фильтрации и не подменяй им подтип создания.
- Канонические технические значения `eventSubtype` находятся в backend `project/apps/transaction/event_serializers.py` (`EVENT_SUBTYPE_CHOICES`), а допустимые значения create API — также в `project/apps/transaction/dto_v2.py`. Канонические русские подписи формы находятся в 101-web `src/localization/messages/ru.ts` (`events.subtypes`), подписи фильтра — рядом в `events.filterSubtypes`; связь с `eventSubtype` задана в `src/domains/events/presentation/core.ts` и `src/domains/events/filters/config.ts`. При расхождении перечитай эти источники, не восстанавливай подписи по скриншоту.
- Точные названия по действующему контракту:

| `eventSubtype` | При создании события | В фильтре/истории |
| --- | --- | --- |
| `project_income` | Поступление по проекту | Поступление по проекту |
| `commission_income` | Агентское вознаграждение | Агентское вознаграждение |
| `company_income` | Поступление в фонд компании | Поступление в фонд компании |
| `project_expense` | Отчёт по проекту | Отчёт по проекту |
| `company_expense` | Отчёт фонда компании | Отчёт фонда компании |
| `project_own_payment` | Оплата или аванс по проекту | Собственные средства проекта |
| `project_working_payment` | Перевод подотчетных средств по проекту | Подотчётные средства проекта |
| `project_to_company_payment` | Перевод из проекта в Фонд компании | Из проекта в фонд компании |
| `company_to_project_payment` | Перевод из Фонда компании в проект | Из фонда компании в проект |
| `company_own_payment` | Оплата или аванс в Фонде компании | Собственные средства фонда компании |
| `company_working_payment` | Перевод подотчетных средств в Фонде компании | Подотчётные средства фонда компании |
| `project_estimate` | Смета по проекту | Смета по проекту |
| `company_estimate` | Смета фонда компании | Смета фонда компании |

- Пример формулировки при записи: `Создаю перевод типа «Оплата или аванс по проекту»`. Не говори `Создаю перевод типа «Собственные средства проекта»`: это подпись категории фильтра.
- «Отчёт» использует существующий контракт расхода, «Смета» — существующий контракт сметы. Не создавай новый MCP-only тип события.
- Позиция может происходить из прайса, существующей сметы или ручного ввода. Сохраняй источник в форме действующего API.
- `startDate` и `endDate` передавай только из явных данных пользователя или существующего события. Если API допускает `null`, не наследуй даты события и не придумывай сроки.
- При точечной правке сначала прочитай полный свежий список, измени только целевую позицию и отправь полный результирующий список по контракту API.
- Если состав или затрагиваемые позиции изменились после исходного чтения, останови запись и покажи конфликт без автоматического слияния.
- Несколько событий создаются серией одиночных create-вызовов. Пакетного payload нет.
