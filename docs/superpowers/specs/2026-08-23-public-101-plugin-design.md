# Публичный плагин 101 для Codex — дизайн версии 2.0.6

## Цель

Сделать Git-плагин 101 устанавливаемым из публичного marketplace любым пользователем Codex без зависимости от приватного зарегистрированного приложения OpenAI. Во всех пользовательских и технических именах оставить только `101`, без суффикса `v2` и без названия `101-private`.

## Текущая проблема

Публичный репозиторий содержит marketplace с техническим именем `101-private`. Плагин `101` через `.app.json` обязательно зависит от приватного приложения `asdk_app_6a8a2c8be2088191b622c8c0fd50d4e8`, обозначенного ключом `101-v2`.

Codex успешно читает публичную карточку плагина, но при проверке обязательного приложения получает `403 Unauthorized`. Поскольку зависимость помечена `required: true`, кнопка установки становится недоступной. Такая архитектура позволяет распространить карточку и навыки через Git, но не позволяет любому пользователю установить полный плагин.

Дополнительно manifest содержит пять стартовых запросов, хотя Codex принимает не более трёх. Лишние запросы игнорируются и создают предупреждения при чтении marketplace.

## Выбранная архитектура

Плагин будет подключать production MCP напрямую по публичному HTTPS-адресу, используя стандартный `.mcp.json`, а не ссылку на приватное приложение OpenAI.

Структура интеграции:

```text
публичный Git marketplace 101
        ↓
публичный плагин 101
        ├── skills/ — сценарии работы
        └── .mcp.json — remote MCP 101
                            ↓
                 https://app.101-group.ru/mcp
                            ↓
                    OAuth пользователя 101
```

MCP-конфигурация использует один сервер с техническим именем `101`:

```json
{
  "mcpServers": {
    "101": {
      "type": "http",
      "url": "https://app.101-group.ru/mcp",
      "oauth_resource": "https://app.101-group.ru/mcp"
    }
  }
}
```

`oauth_resource` совпадает с каноническим защищённым ресурсом production MCP. Сервер уже публикует OAuth discovery, поддерживает dynamic client registration, PKCE и loopback callback Codex Desktop. Данные компании не входят в Git-пакет и становятся доступны только после пользовательской OAuth-авторизации.

## Именование

После изменения используется одна идентичность:

- marketplace `name`: `101`;
- marketplace `interface.displayName`: `101`;
- plugin `name`: `101`;
- plugin `interface.displayName`: `101`;
- MCP server key: `101`;
- пользовательское название подключения: `101`;

Названия `101-private`, `101 Private`, `101-v2` и `101 v2` удаляются из manifest, marketplace, README и тестов. Исторические Git-коммиты и release notes не переписываются.

## Поток установки и авторизации

1. Пользователь добавляет публичный Git-репозиторий как marketplace с ref `main`.
2. Codex читает marketplace `101` и manifest плагина `101`.
3. Кнопка установки доступна, поскольку package больше не требует приватный `asdk_app`.
4. Codex устанавливает skills и конфигурацию remote MCP.
5. При первом вызове инструмента MCP отвечает Bearer challenge со ссылкой на OAuth discovery.
6. Codex регистрирует публичный OAuth-клиент, открывает авторизацию 101 и получает пользовательский токен.
7. Последующие MCP-вызовы выполняются с правами авторизованного пользователя.

## Ошибки и поведение

- Если production MCP недоступен, плагин остаётся установленным, а подключение сообщает сетевую ошибку без повреждения skills.
- Если OAuth отменён или запрещён, плагин остаётся установленным, а инструменты 101 недоступны до успешного подключения.
- Если сервер вернул неподдерживаемый OAuth resource, проверка релиза должна завершиться ошибкой до публикации.
- Приватные `asdk_app` больше не участвуют в установке и не могут заблокировать кнопку.
- Новый marketplace с именем `101` не должен сосуществовать с локально установленным старым `101-private` во время приёмки; старый checkout и cache проверяются и удаляются отдельно перед чистым smoke.

## Проверка

До выпуска необходимо выполнить:

1. JSON-парсинг marketplace, plugin manifest и `.mcp.json`.
2. Repo-тесты `python3 -m unittest discover -s tests -p 'test_*.py' -v`.
3. Валидацию plugin-creator для `plugins/101`.
4. Проверку отсутствия `101-private`, `101 Private`, `101-v2`, `101 v2` и приватного app ID в актуальных файлах пакета и документации.
5. Проверку production OAuth discovery и неавторизованного Bearer challenge для `https://app.101-group.ru/mcp`.
6. Чистую установку marketplace в Codex: карточка `101`, активная кнопка установки, установленная версия `2.0.6`.
7. Новый task после установки и минимальный read-only smoke через `whoami`.

## Граница выпуска

Готовность исходников и локальные тесты не означают готовность релиза. Версия `2.0.6` считается выпущенной только после merge в `main`, Git tag/release, обновления marketplace checkout, установки cache версии `2.0.6` и успешного OAuth/read-only smoke из новой задачи Codex.

## Вне scope

- изменения backend-кода 101;
- изменение бизнес-контрактов или списка MCP-инструментов;
- изменение аналитических виджетов;
- публикация приложения в отдельном облачном каталоге OpenAI;
- миграция исторических Git-тегов и старых установок.
